# 実装の判断と境界

原作のルール・乱数・入力待ちをCに残し、表示・入力変換・保存をRustで担当する。原作との差分と周期は [原作仕様との対応](ORIGINAL-SPEC-ja.md)、意味データと名称は [日本語化の契約](LOCALIZATION-ja.md)、地図の観測と画像は [地図表示の契約](MAP-DISPLAY-ja.md) を参照する。

## 状態の所有者

| 担当 | 実装 | 所有する状態・判断 |
|---|---|---|
| Cロジック | `logic/core.c`、`command.c`、原作の各ルール、`knowledge.c` | 生成・戦闘・移動・ターン・RNG・探索記憶・同期入力待ち |
| 表示 | `rust/crates/display/` | 翻訳、ゲームウインドウ、公開済み所持品の描画、観測地図・足元・効果、不変フレーム、`animation::Animator` によるキャラクターの表示時計・クリップ再生 |
| 入力 | `rust/crates/input/` | 物理入力から原作キーへの変換、UTF-8編集、持ち物メニューの選択と操作予約 |
| プラットフォーム | `rust/crates/platform/` | checkpoint、消費済み入力journal、再生位置、保存envelopeと検証 |
| ゲーム側の接続 | `rust/src/lib.rs`、`host.rs`、`startup.rs`、`runtime.rs`、`session.rs`、`engine.rs` | C/Rust FFI、型付き開始設定・転送allocation・libc環境サービス、Bevy Appの組立て、各層への状態投影と実行順 |
| ブラウザー側の判断 | `rust/crates/browser-display/src/controller.rs`、`policies.rs`、`display/src/browser_ui/`、`widgets.rs` | 開始・終了・保存の状態、Worker世代、IME制限、入力検証、表示設定、履歴、配置・フォーカス・カメラ・タイル計画 |
| ラスタライズ | `rust/crates/raster/` | PNG decode、画像回転・拡大・合成、図形・SVG path・クリップ・透明度、フォント計測・shaping・文字の画素、完成RGBA |
| ブラウザー資源 | `rust/crates/browser-display/src/browser/` | イベントlistener、完成RGBAの転送、ネイティブ文字入力、画像bytesとcache、Worker/SAB、IndexedDB、保存候補bytes、ファイル・Blobの所有とAPI実行 |

入力は表示が公開する不変の `InputView` を参照する。基本の入力待ち・所持品行と、持ち物の詳細・操作候補を付けた描画用UIは区別する。入力Pluginは翻訳を再実行せず、表示状態や地図Componentを直接変更しない。文字編集の消費byte・未送信byte・表示可能な文字列は入力の `State` が所有し、接続部が表示へ一方向に投影する。開始時に表示する既存値は、空のC編集bufferを埋める入力にはしない。

プラットフォームの `Session` は内部状態を非公開にし、新規開始・復元・checkpoint更新・キー消費をAPIで扱う。checkpointとjournal/replay cursorを個別に組み立てず、所有者がまとめて更新する。接続部の借用ビューは各層を明示し、別層の状態へ暗黙にアクセスするDerefは持たない。名前と持ち物の表示用コピーは接続部が投影する値で、表示から正本を書き換えない。

表示から入力への依存はなく、プラットフォームは表示・入力に依存しない。3層のクレートではunsafeを禁止し、FFIは接続用クレートに限定する。表示は新しい観測フレームの足元から配置可否と階段操作を公開し、入力用snapshot・画面・保持フレームで同じ観測を使う。格子は80×24・ASCII 1,920 bytes・範囲内のプレイヤー座標を境界で検査し、不正な観測は既存フレームを置き換えない。

## 実行とABI

契約の正本は [contract/rogue_abi.h](../contract/rogue_abi.h)。固定幅整数と借用byte列を渡し、CのWINDOW・THING・FILE・生の関数ポインターは公開しない。ABI定数は同じヘッダーからRustの `rogue-contract` へ生成する。Cが確保した保存bufferは接続部の `CoreSaveBuffer` が所有し、失敗経路を含めDropで `rg_core_save_free` を一度だけ呼ぶ。復元に貸すbufferは別の不変allocationで、後のcheckpoint差し替えでも寿命を保つ。

CゲームスタックはWorker内で同期実行し、入力キューが空ならAtomics.waitで待つ。空キューをEscや仮の入力として扱わない。Asyncifyは使わず、新規ゲームと復元には新しいWorker/Wasm instanceを作る。

ゲーム本体はstandalone reactorの `build/game.wasm` で、Worker側RustがWebAssembly APIでcompile・instantiateし、`_initialize`、`rg_configure`、`rg_run` の順に呼ぶ。`rust/src/startup.rs` が開始設定の正本であり、言語・trace・メッセージ送り方針・復元JSONを型ごとに検証する。未知のフィールドと不正な型を拒否し、成功した設定は同じinstanceで差し替えられない。ゲーム開始時に一度だけ消費する。fixture指定は `test-hooks` のbuildだけが受け付ける。

Workerの `Transfer` は `rg_alloc / rg_dealloc` で確保元のゲーム側Rustへ転送bufferを返す。確保元はpointerとlengthの組を保持し、未知・重複・不一致の解放を行わない。`rg_configure` は借用byte列を同期区間でコピーして所有し、その後の転送buffer解放に依存しない。開始設定や復元byte列を仮想ファイルへ書く処理はない。

`rogue-layers` のBevy Appには表示・入力・プラットフォームのPluginを登録し、CのFFI呼出しに合わせて `App.update()` を行う。SystemSetの順序は **Presentation → Input → Journal → AcceptedInput → Frame → Save**。時間経過やブラウザーの再描画だけでCのcommand・look・RNGを呼ばない。

メインスレッド用の `build/browser-ui.wasm` は停止中のゲームWorkerとは別instanceである。ゲーム画面の上のタイトルはHTMLの `header.heading` に置き、Rustのdocument命令で言語を反映する。HTMLタイトルは「元祖 ローグ · 5.4.4」を表示する。トップの開始フォーム、地図、HUD、ログ、設定、ゲームウインドウはCanvas2Dへ描く。PC・スマホともトップ右上は全画面ボタンだけにし、設定ボタンはゲーム中に表示する。トップの再開操作は `resume.rs` が「前回の続き」を描き、GitHubリンクをその次にだけ置く。透明なネイティブinputはIME・文字編集・選択範囲・クリップボードの受取りに使う。

設定はPC・スマホ共通の `browser_ui/settings.rs` で描く。先頭行は全画面アイコンボタンと操作ボタンの表示切替アイコンボタン。その下にボタン配置・ボタン割当の編集を置き、アニメーション切替、利き手、テーマ、マップ表示の順に並べ、その下にトップへの復帰と「冒険を終える」を同じ行に置く。利き手はアニメーションと同じ切替部品で右・左を選ぶ。手動保存・保存の書き出し・セーブファイルから再開はトップ・設定とも非表示にする。倍率の部品とセンタリングは設定に置かない。表示言語はトップで選ぶ。名前・シード・ランダム選択・新規開始・前回の続きはトップだけに置き、GitHubは再開ボタンの下に置く。設定には保存・再開の結果とエラーだけを出し、ゲームのメッセージや常設の説明文を出さない。 入力エラーは名前・シード・文字入力の各欄直下に表示し、編集時に消す。長さと使用不可文字の原因を分け、履歴へ残さない。開始・復元の読み込み表示は処理中だけにし、開始・入場・復元完了・トップ復帰・終了・先行入力取消とSの保存説明は画面・履歴へ出さない。PC・スマホとも保存処理・結果・失敗を表示する。

`browser_ui/dropdown.rs` は選択肢の最長の文字幅をRustのフォントで計測し、余白と開閉アイコンを含む幅にする。高さは48px以上を保ち、設定行の残り幅いっぱいには広げない。開閉アイコンはRustのベクター描画を使う。

## 目的地への自動移動

PCのクリックとスマホのタップは、描画と同じcameraで地図の目的地へ戻す。`browser-display/src/autowalk.rs` は現在公開されている `map_cells` と観測済み足元だけを使い、8方向の経路を作る。空白・壁・不明な地形は通らず、斜めは両側の直交セルが公開済みで通行可能な場合だけ使う。表示済みの敵は途中経路へ入れない。歩く場合は、その敵を目的地に指定した時に限り最後の通常移動で一度攻撃できる。走る1・走る2は原作の停止判定を優先し、走る1は敵との衝突で一度攻撃して停止し、走る2は隣接した時点で手前に停止する。Cの未公開地形・罠・敵や移動可否を問い合わせない。

移動形式はクリック・タップにも適用する。歩く場合は通常command待ちごとに前の1歩の確定位置と最新の公開経路を照合し、100msの単発タイマー後に通常移動キーを一つだけ送る。走る1・走る2では専用開始値で原作のShift・Ctrl走行を一度開始し、原作look(TRUE)後にまだrunningが続く時だけ現れるrun-boundary待ちへ、公開経路の同じ方向の直線区間を最大80歩のpermitとして送る。開始値自体は移動しない。ゲーム側の `input::target_run::Permit` は原作の各入力境界で通知sequence・SABの割込epoch・走行方向・確定位置・最新の公開地図を再確認し、一歩分のCONTINUEへ変換する。原作のdoor_stop・firstmove・passgoと停止判定を各歩で保持し、Ctrlを毎歩送り直さない。目的地ではSTOP、経路が曲がる時はSTOPで通常command待ちへ戻した後、次の直線区間を開始する。原作が自然停止したら通知と通常command待ちで経路を終了し、自動再開しない。手入力の処理中に目的地を指定した場合は次の実入力待ちまで保留する。同じ要求への二重送信、未確定の移動の積み上げは行わない。

走行permitの間は移動だけの中間frameを最新の一枚へまとめ、hostとの一歩ごとの往復待ちを除く。攻撃・負傷のactor event、投射物eventを含むframeは保留frameを先に送ってからそのまま公開する。方向・文字・一覧等の入力待ち、停止、終了でも保留frameを送る。Cの各行動・look・描画観測を省略する処理ではなく、ルール・RNG・通知順は維持する。

何らかの操作入力、敵からの攻撃（missを含む）、敵への近接攻撃、罠の発動で経路と予約タイマーを破棄する。Cは `attack`、`fight`、`wake_monster` で成立した凝視、敵の光線が主人公へ実到達した `fire_bolt`、浮遊を除く `be_trapped` の成立箇所から `rg_host_player_event` を呼ぶ。Rustはinstance内sequenceを付け、次のframe・入力要求より先にWorkerへ公開する。通知はプレイヤー自身の種別だけを持ち、攻撃者の位置・正体や罠の種類を持たず、英文ログやHP差から中断を推測しない。到達、次歩の失敗・予期しない位置、経路消失、入力ウィンドウ、scene・階層・Workerの変更、終了、blur・非表示・pagehideでも停止する。新規開始・ロード中と再生中には自動移動を開始せず、古い世代の通知・タイマーは新しいsessionへ作用しない。通常移動ではすでに送信した一歩を除き、停止後の入力は残さない。走行の手入力・表示操作による取消はSABの割込epochでも伝え、処理中の原作行動が完了した後の入力境界で未消費permitを破棄する。

run-boundaryのUI投影は通常command待ちとし、Web操作・方向ボタン・物理キーを受け付ける。内部では専用待ちを保持し、停止はSTOPを一度だけ送って解放する。同じ操作で届いた手入力はSTOPの後に一度送り、通常commandで消費する。復元後に経路を持たない専用待ちもSTOPで解放し、余分な一歩を許可しない。

経路、目的地、タイマー、sequence、割込epoch、未消費permitは保存対象にしない。permitの転送値自体はjournalへ入れず、実際に消費した通常移動キーと専用runの開始・CONTINUE・STOPだけを既存journalへ記録し、ルール・RNG・ターン・保存形式はCと既存の保存経路が所有する。hoverの地形説明と、6pxを超える地図drag・二本指pinchの表示操作は維持し、それらを目的地tapに変換しない。

## スマホの操作部品

幅700 CSS px未満またはcoarse pointerでは、独立ファイル `display/src/browser_ui/mobile.rs` が画面を構成する。ゲームWorkerはBevy Appを使うが、ブラウザーの画面遷移は `browser-display::Controller` の `topOpen`・`starting`・`running` 等で管理する。スマホのトップは独立部品 `mobile_top.rs` がこの状態に従って描き、タイトル・名前・シード・新規開始・ロードを表示する。保存がない場合はロードを無効にし、入力エラーだけを表示し、通常の通知や説明文は出さない。狭い横画面ではトップ内をスクロールできる。開始中は読み込み表示を出す。

スマホではゲーム開始・ロード時からHTMLタイトルの下にゲーム領域・全画面・設定・操作パッドを出す。設定から操作パッドを隠しても、次の開始・ロードでは再び表示する。PCでも開始・ロード時から操作パッドを表示し、設定の表示切替で隠せる。表示設定は設定内から使える。再描画・直前のメッセージ表示・シェル起動・版表示は操作項目に出さない。原作のQは `main.c:quit` が終了結果と金額を確定して得点画面へ進むため、「冒険を終える」として残し、原作の確認を使う。肯定した終了では `score` の `flags == 1` に限り得点前の空画面だけを省略し、得点を表示する。死亡と勝利の結果・精算を読むための待ちは維持する。新規開始と前回の続きは設定の「トップ画面に戻る」からトップへ移って行う。

PCの下部操作欄は `display/src/browser_ui/desktop.rs` と共通の `controls_editor.rs::draw_configurable_dock` が担当する。地図と右側のログの下に専用領域を確保し、8方向・待機と常設12操作を配置する。左利きの既定配置は、上段が移動方式・持ち物・武器・防具、中段が探す・投げる・杖・巻物、下段が繰返し・全体図・食べる・飲むの4列3段で、パッドを左に置く。右利きではパッドと操作列の左右を反転し、パッド内の8方向は自然な方位のまま保つ。階段・拾う・罠調査と、弓装備中の「矢を撃つ」は上段へ状況に応じて追加し、常設操作を置き換えない。矢がなければ「矢を撃つ」を無効にする。持ち物・設定・履歴等のウィンドウ中は背景操作を受け付けない。全体図はスマホと同じ公開地図の描画を共有する。

ボタンの配置と割当は `control_preferences.rs` の論理列・スロットとコマンドIDで管理し、PC用12操作とスマホ用6操作を独立して `rogue-controls-v1` へ保存する。配置編集では二つのボタンをドラッグで交換する。方向パッドは配置・割当のどちらの編集でも一塊として扱い、ドラッグで一列全体を交換する。割当編集ではボタンを選んで共通のコマンド一覧から実行内容を選ぶ。編集画面はゲームを暗く表示し、ゲームへの入力を遮断する。「決定」で変更を保存してゲームへ戻り、「取消」とEscは破棄して戻る。「デフォルト」は現在の編集対象の配置または割当だけを下書きへ復元し、編集画面に残る。確定前には永続設定を書き換えず、PC・スマホの表示種別が変わるresizeでは下書きを破棄して設定画面へ戻る。コマンドの実行・可否・キー表記は共通のregistryを使い、ボタンの短い表示名だけを用途に合わせる。状況別探索の役割はprofileの `contextual_search` に論理ボタン番号で保存し、配置交換ではボタンと一緒に移動する。別コマンドの割当で役割を解除し、割当のデフォルト復元で既定の状況ボタンへ戻す。旧 `web.context` は探索とこのUI役割へ移行する。旧キーは既存の探索キーを優先し、衝突しない別名だけを最大8件まで追加する。

PCの方向待ちは `direction_overlay.rs` が8方向と中央の取消を描く。クリックした操作ボタンを起点として、品物選択を挟んでもその付近へ表示し、画面端では全体を画面内へ収める。キーボードから開始した場合は過去のクリック起点を消し、中央へ表示する。操作欄の表示・非表示にかかわらず同じ選択部品を使い、方向待ち中の常設操作は位置を保って無効にする。8方向はテーマの強調色と背景色の文字で示し、取消は通常の表示を保つ。画面構成と配置profileは共通の `compact_layout()`（幅700px未満またはcoarse pointer）で選び、PC向け入力・キー表記・編集機能は `pc_controls()`（coarse pointerでない場合）で判定する。狭幅PCでも品物選択タブ、ヘルプ・ログのキー情報、再割当を反映した履歴キーを保つ。通常パッドと方向選択は同じ方向部品を使い、PCでは実際の割当キーを矢印の下へ表示する。方向待ちは通常移動への割当を単一方向へ解決し、走行方式を適用しない。PCの方向待ち中は共通可否判定で背景の操作欄・headerを無効にし、実スマホでも全体図を無効にする。

操作は共通のコマンドIDから既存controllerと公開済み `frame.ui.map_controls` へ接続する。PCの投げるt・杖zは専用キーで品物を先に選び、その後に同じ方向待ちへ進む。通常command待ちで公開する `command_items` を表示し、品物確定まではCコマンドを送らない。確定後は既存pendingへ品物を予約し、Cにはt/z・方向・品物の原作順で渡す。方向取消・失敗で予約を破棄し、方向待ちで保存した場合は新instanceでも予約を一度だけ継続する。スマホと原作の通常t・zは方向を先に選ぶ経路を保つ。持ち物・投げる・アイテムのアクション等は既存 `draw_dialog` と同じdescriptorを使い、アイテムの内容と入力候補を変更しない。`mobile_dialog.rs` は公開済みの入力kind・window kindから選択肢の文言とPC用のボタン内キー表記を作る。ボタンの操作やキーは本文・フッターへ重複表示せず、質問文の一覧キー案内も省く。スマホはキー注記を付けない。設定・ステータス・ログ履歴・操作一覧は共通の `sheet_layout` で内容に合わせた高さを使い、画面内に収まらない場合だけ本文をスクロールする。設定の行間は12px、下端余白は16pxとし、回数入力はエラーがある時だけエラー行の高さを加える。トップの「前回の続き」はIndexedDBの保存を読み出し、検証後に新Workerへ復元する。

新規操作部品の下限を48×48 CSS px、頻用の方向パッドを52×52 CSS px、文字の通常サイズを17 CSS pxにする。[WCAGの44×44 CSS px](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) と [Androidの48dpタッチ領域](https://support.google.com/accessibility/android/answer/7101858?device=c&hl=en) を踏まえ、連続して押す方向には余裕を追加する。文字は [Appleの標準本文17pt](https://developer.apple.com/videos/play/wwdc2020/10175/) を参考にした本UIの通常サイズであり、CSS pxとpt/dpを物理寸法として同一視せず、万人共通の医学的下限とは扱わない。既存ゲームウインドウの内容・部品はこの追加UIで作り替えない。

Web固有操作の正本は `display/src/browser_ui/actions.rs`。移動方式g、全体図p、射撃x、設定回数での繰返しE、回数設定A、コマンド一覧C、Web設定O、全画面G、操作パッド表示V、全履歴Mを定義し、PCボタンのキー表示・物理入力・PC参照表・スマホ操作一覧が同じ定義とactionを使う。原作のaは前コマンド1回、oは原作設定のまま保つ。PCの上部アイコンはボタン内へキーを表示し、方向・待機もパッド内に表示する。繰返しボタンは実行Eと回数設定Aを区別する。操作パッドを隠してもWebキーは使える。

持ち物ウィンドウは、タイトルの文字サイズと同じ20px高の「アイテム履歴」ボタンをタイトル横に置く。その下のタブは「すべて・装備中・杖・食べ物・薬・巻物・武器・防具・指輪・護符・金貨」の順とし、所持品の公開descriptorに一致する項目があるタブだけ表示する（すべては常設）。タブ行は横スワイプ・ドラッグ・ホイールでスクロールする。絞り込みはBrowserUiの描画だけで行い、入力層が参照する全所持品の装備枠情報を維持する。閲覧タブと縦・横位置の正本はBrowserUiに置き、新規冒険の開始検証成功時に「すべて」・位置0へ初期化する。新規開始では冒険中の移動方式を歩くへ、全体図と一時縮小を通常表示へ、ログを位置0・新着追従へ戻す。「つづきから」ではこれらの現在状態を変更せず、表示方式・通常倍率・アニメーション・利き手・テーマ・ボタン配置・割当とキー設定も開始方法によらず保つ。未送信の記号質問欄は一時入力なので、新規・復元とも開始検証成功後に空にし、検証失敗では保つ。同じ冒険では閉じて再表示・詳細から戻る・再読み込み後の「つづきから」でも最新の閲覧状態を保つ。localStorageのrogue-inventory-view-v1はversion2でactive・保存slot用view・旧形式fallbackを分ける。C保存bytesは変更せず、IndexedDBの同一transactionで別keyのmanual.inventoryへtokenとviewを添える。save成功時だけslot所有を更新し、所有中の閲覧変更をslotの最新viewへ反映する。未保存の新規冒険は旧slotのviewを変えない。復元はCの最初の入力待ちでview候補を採用し、失敗時は現在viewを保つ。token不一致はslot側snapshot、旧sidecar無しは旧形式fallback、それも無ければ既定viewを使う。選択した種類がなくなった場合はすべてへ戻し、位置は現在の表示範囲内に収める。「アイテム履歴」は一覧のC待ちを閉じてから原作の発見一覧Dを開き、入力kindがdiscoveryのときだけ全件選択の*を自動で渡す。種類選択の中継を省くが、Cのdiscovered→print_disc→set_orderと乱数による順序決定を維持する。Dと*は通常と同じキーとしてjournalに記録し、復元時には記録済み入力を再生する。ゲーム画面からのキーボードDは原作どおり種類選択を開く。固定50ターン休息は一覧に置かない。

PCのログ見出しは通常時に既存の一覧アイコンを文頭へ表示し、地図のhover中は公開済み `map_tiles` の画像と名前を表示する。画面上のポインター位置から現在のカメラと公開フレームを使って毎回引き直し、未公開の地形・正体・種類は参照しない。ASCII表示でも既存tiles画像を使う。暗闇の黒画像には周囲と区別できる小枠を付ける。これらの描画やhoverはC入力を送らない。

品物選択は共通の `rg_item_choices` が公開する候補と要求typeの `item_filter`、`get_item` の `item_action` を使い、`Presentation` は選択目的を `input.action` へ投影する。識別巻物の追加対象は使用する巻物の選択と別の見出しを持ち、対象カテゴリをCの候補から限定する。`input.choose_item` と一覧再表示後の `input.choose_item_list` は共通の品物選択ウィンドウを使い、PCの候補行は持ち物欄と同じデザインと種類タブを使う。武器・防具・薬・巻物・食べ物・指輪・杖の操作は対象の種類だけ、投げる・落とす・単品照会Iは「すべて」だけを表示する。種類限定の識別は原作の対象typeを使い、指輪／杖の識別はその二種類、MASTERの任意識別は「すべて」にする。名付けは公開された候補の種類だけを表示する。対象のカテゴリ名は品物descriptorと同じCのsemantic変換を再利用し、Rustでコマンド別の対象分類を重ねない。filterは本文へ表示せず、choicesと同じ入力待ちの終了時に消去する。選択窓のタブとスクロール状態は閲覧用の保存設定とは分離し、アイテム履歴ボタンは閲覧窓にだけ置く。スマホの候補操作は既存の配置を維持する。候補を直接選べるため重複する「一覧を開く」ボタンは置かず、物理キーの `*` はそのまま原作へ送る。原作の一覧が1品で待たずに戻る場合も、一覧を要求した状態を次の選択見出しに残す。追加の確認入力や自動の対象決定は行わない。単品照会Iは原作が `*` を受け付けない契約を維持する。方向・識別対象・左右の手・名付け・検出結果の確認は、それぞれCが要求した入力待ちに従い、使用後の通常操作まで接続する。

入力を求める質問は `browser-display/log_visibility.rs` が意味IDと入れ子の意味引数から分類し、`transient_prompt` としてPC・スマホのゲームログ、全履歴、公開観測のメッセージから除外する。方向・品物・識別対象・左右の手・命名・確認などの現在の質問は既存の入力ウィンドウ／操作部品で示す。原作メッセージと内部履歴は保持し、命名画面が今回の使用効果を取り出す区切りにも使う。結果の疑問文やユーザーが付けた品名は文字列で判定せず、そのまま表示する。

「全体図」は操作欄のボタンで開閉する確認用の独立部品 `mobile_map.rs`。現在の公開地図を幅に合わせて色分けし、タイトルは出さず、17pxの凡例を一行で付ける。同じボタンをもう一度押すと通常表示へ戻り、入力decoderやゲームウインドウを変更しない。詳細は地図表示の契約に定義する。

状況別操作は通常「探す」で、公開された足元と現在の入力状態から、階段上では「下りる」（護符取得後は「上る」）、足元のアイテムには「拾う」、足元または隣接する観測済みの罠には「罠調査」へ切り替える。罠調査は原作の方向選択を移動パッド上で開く。階段の可否と浮遊中の拾得不可は読み取り専用のplayer_stateを使い、品名やログから推測しない。スマホでは通常の「探す」から切り替わった状況別ボタンだけをテーマの強調色と背景色の文字で表示する。リストは分類された操作を常時列挙し、現在の入力待ちでは実行できない操作を無効にする。階段操作は公開された階段の可否、拾う操作は公開された足元の品物と浮遊状態に従って無効にし、状況別ボタンと重複する項目も非表示にしない。スマホの六つのボタンは既定の配置を保ち、配置・割当の編集をスマホ用設定へ保存する。

一覧・設定はボタン上からのタッチスワイプでスクロールでき、移動した押下は実行しない。倍率は地図上のピンチ・ホイールで変え、表示方式に共通の連続した8〜128 CSS px/セルを使う。Rustの `gestures.rs` がピンチの比率とホイールの連続アニメーションを計算し、Rustのブラウザー層がrequestAnimationFrameを登録する。原作に拡大縮小処理を追加しない。操作中心の地図位置を維持する。PC・スマホ共通の移動・待機パッドはマウス・タッチの押下時に既存キーを一度送り、350msの長押し後は100msごとに、前の入力が処理され新しいcommand待ちになった場合だけ同じキーを送る。解放・取消・ポインターの移動や画面外への離脱・ウィンドウ表示で反復を止める。方向待ちは解放時の一回だけを使う。スマホの投げるt・杖z・自動戦闘f/F・拾わずに移動m・罠調査^の全6操作で、操作パッドを表示している間は同じ移動パッドを強調表示する。パッドを隠している場合はスマホの共通方向選択ウィンドウを使い、PCはパッドの表示設定にかかわらず近傍または中央の方向小窓を使う。いずれも8方向と取消をクリック・タップ・キーで選べるようにする。原作get_dirは8方向とEscだけを受け付け、自分方向を受け付けないため中央キーは出さない。修飾キーは方向待ちで単一の通常方向へ正規化し、走行を開始しない。操作一覧・履歴・ステータスウィンドウ中は背景のゲーム入力を遮断する。PC入力方式へ切り替わる場合はスマホの操作一覧を閉じる。表示・一覧・倍率・全画面・resizeでC状態、RNG、入力回数を変えないことをPlaywrightで検証する。原作の@では端末画面のメッセージhashは変わるが、ターン・ルール状態は維持する。

| `rg_core_save_bytes / rg_core_load_bytes` | `rg_host_checkpoint / rg_host_restore_data` と保存・復元 |

色の正本は `web/themes.json`。ウインドウの背景・枠、本文・ボタン、選択・スクロール、HUD・装備パラメータを役割別に定義する。現在の配色をdefault、緑と黒の配色をgreen-blackとして持ち、設定の「配色」プルダウンはJSONのテーマ一覧を使う。その直下の「表示方法」にマップ表示プルダウンを置き、項目名は左、選択部品は右に揃える。`theme.rs` が読み込み時にID・色書式・役割の一致を検査し、`Widgets` は色の役割だけを解決する。任意の文字列や品名を置換しない。色JSONはUIのWasmへ組み込むため、編集後は `build-ui.ps1` で再ビルドする。

選択したthemeは既存の `rogue-map-display-v1` に表示方式・倍率・アニメーション・利き手と共に保存する。利き手は右を既定とし、旧設定での省略・不明な値も右へ戻す。旧設定・不明なIDはdefaultへ戻し、表示方式等の有効な値は保つ。切替は再描画とdocumentのCSS変数更新だけを行い、C入力・乱数・保存本体へ触れない。配色のCSS変数とtheme属性はHTMLのゲーム領域 `#canvas-stage` へ限定する。HTML外枠と左上見出しは固定の黒背景・白文字を使い、ゲーム配色から分離する。green-blackではUIの色付き絵文字をalphaマスクとして指定色で描き、defaultのカラー描画は維持する。地図記号・全体図・検出図の色は共通map_colorsに置き、テーマ選択で変えない。画像素材の画素も変更しない。

## ブラウザー資源と残るJS

ブラウザーAPIは `wasm-bindgen / web-sys / js-sys` の生成bindingを通してRustから呼ぶ。製品の手書きJSはWasmの起動だけを担当する。生成bindingは実行中もブラウザーAPIへの呼出し・値の受渡し・callback接続を行うため、JS全体を起動時だけ実行するという意味ではない。ゲームの状態・入力・描画・保存の判断や処理は原作CとRustが所有する。`browser/mod.rs` はDOM・listener・座標変換・再描画の登録を、`paint.rs` は完成RGBAの転送と公開UIの意味的なDOM mirrorを担当する。listenerは弱参照でBrowserへ接続し、callbackの寿命をRustで保持する。`effects.rs::WorkerSlot` はWorker・共有キュー・callbackを所有し、Dropでキューをcloseしてcallbackを外しWorkerを終了する。`queue.rs` はSAB/Atomicsの容量検査・全公開または全拒否・待機・flushを実装し、生の整数を解釈しない。

`saves.rs` はIndexedDB transaction完了・ファイル選択・Blob書出しを扱い、候補bytesと採用済みbytesはBrowserの別領域に保持する。ファイル選択と全画面のAPIはユーザーイベントの同期区間で開始し、完了はRust futureで待つ。`images.rs` は取得bytesをRustのPNG decoderへ渡し、decode済み画像と回転cacheを所有する。`worker.rs` はstandalone Wasmの初期化・開始設定の転送・同期C起動・親への転送を担当する。

`browser/values.rs` はブラウザーのUTF-16文字列とRustのUTF-8、JSON値とブラウザーのobject/arrayを変換する。深さ・循環参照・数値を検査し、ブラウザー由来の孤立surrogateには置換文字を使う。`tools/bind_browser.py` は生成bindingの文字列ABIをこのRust codecへ接続し、使用するwasm-bindgenの版と生成形状が一致しない場合に生成を失敗させる。生成JSにJSONの直列化・解析や文字列のencode/decode処理を置かない。

`rogue-raster` は表示層の描画命令を受け取り、tiny-skia・svgtypes・swash・pngを使って全画面のRGBAをRust内で作る。ブラウザーへは `putImageData` で完成画像を一度だけ転送し、Canvasの図形・文字・パス・画像描画や文字計測を使わない。文字計測と描画は同じglyph planとtop基準を使い、同梱Noto Sans JPの400/600とNoto Color EmojiをRustで読み込む。文字幅はOSのフォントに依存させない。PCのEnterキー表記は共通部品で `Enter` とし、同梱フォントに字形のない記号を使わない。辞書と共通キー表記はglyph ID 0（欠字）を検査し、実ブラウザーの描画文字列も同じ検査に渡す。ドット絵の32px回転と最近傍拡大を保ち、図形・透明度・クリップ・輪郭もRustで計算する。PNGはbuffer確保前に寸法・画素数・bytes上限を検査する。フォントの取得・解析に失敗した場合はRustが可視の起動エラーと再読み込み操作を出す。

整数のデバイス座標に置く不透明・無回転の画像は、Rustが最近傍の画素選択と直接転送で描く。各画像は直近の拡大サイズ・左右反転に対応する画素を一組だけ保持し、同じ条件の描画では行単位で転送する。追加cacheは一画像あたり65,536画素までとし、元画像は変更しない。端数座標・半透明・画像回転・上限を超えるサイズは汎用合成経路を使う。入力と共通のメインスレッドで、同じ拡大計算や毎画素の浮動小数点shaderを繰り返さないための分岐で、両経路の拡大・反転・クリップ・alphaを画素で照合する。

整数境界のクリップは既存maskの該当範囲をコピーし、端数境界は汎用経路で合成する。完成maskは親から続く全クリップ矩形・surface寸法・pixel ratioをキーとして再利用する。RendererがLRUで最大8件・合計16MiBを保持し、surface寸法変更時に破棄する。固定の画像manifestもモードごとに一度だけ解析し、描画計画とフレーム検証は同じ不変定義を参照する。

入力転送とWorker通知の内部応答では、地図・履歴・描画命令を含む観測用snapshotを生成しない。snapshotは描画と明示的な観測要求で作る。BrowserUiからControllerへの描画命令列は所有権を移し、一式を繰り返し直列化・複製しない。

キーのCへの転送と、その成功通知だけでは古い画面を再描画しない。`Controller` が応答の `redraw` で更新要否を通知し、ブラウザー層はそれに従って描画を予約する。Workerから届く新しい画面・入力待ち、ローカルUIの変更、エラー、未完了モーションの中断は即時の描画対象にする。長押しの反復と連打は同じ入力キューへ全て渡す。Cは入力を消費して処理結果を公開し、描画の予約・実行・モーション完了を待たずに次の入力を処理する。描画は最新の公開結果を使い、描画前に複数の結果が届いた場合は途中の画面を省く。アニメーションのstepは公開イベントの優先選択にだけ使い、ゲームのターン進行を制御しない。時間によるアニメーション更新は専用タイマーが継続する。

素材ギャラリーも共通のWasm起動だけを使う。`browser/gallery.rs` がmanifest・PNG・atlasの切出し・再生時刻・停止再開・フレーム選択を所有し、元画像とsheetを含む完成RGBAを転送する。HTTPの作品サーバーから開く。素材生成・検証用JSは `tools/`・`tests/` に置き、製品から読み込まない。境界検査は `web/` 以下を再帰走査し、HTML内scriptも対象にする。

ゲーム側のホスト接続は `rust/src/host.rs` の固定幅raw Wasm importsで、Worker側Rustのcallbackを `rogue` namespaceへ登録する。ゲーム側のAPIは借用sliceを同期区間だけ渡し、Worker側Rustは毎回現在の `WebAssembly.Memory.buffer` を取得してアドレス・長さを検査し、Rust所有のbyte列へコピーする。メモリー成長前のviewを保持せず、元のsliceの解放前にコピーを終える。JSON・UTF-8の復号と保存byte列の転送もWorker側Rustが担当する。

ゲーム側の `runtime.rs` が空の環境変数・固定した作業ディレクトリー・時計の単位変換・stdioの上限検査とbyte列結合を実装する。非対応のOSファイル操作はエラーを返し、stdout/stderrはRustの診断channelへ渡す。WASIの `proc_exit` はWorker側Rustで異常終了として扱う。Cのlibc・allocator・standalone supportはWasm内で動き、メモリー成長とsetjmp/longjmpもWasm内で完結する。ビルドでは `STANDALONE_WASM / FILESYSTEM=0 / WASM_BINDGEN=0` とWasm EHを使い、EmscriptenのJSランタイムを配布しない。墓碑の年は死亡時にブラウザーが観測した現地年をRust経由で受け取り、standalone libcのUTC timezoneに依存しない。

| JS | 残る接続の責務 |
|---|---|
| `web/app.js` | 生成bindingとWasmを読み、Rustのブラウザー起動を呼ぶ |
| `web/worker.js` | classic Worker内で同じbindingとWasmを読みRustを起動する。Rust起動前の取得・初期化失敗だけ親へ通知する |
| `build/browser-ui.js` | wasm-bindgenのブラウザーAPI binding。Rust codecへの接続、API実行・値とcallbackの受渡しを担当する |

サーバーへのプレイ記録送信は行わない。復元に必要な消費済み入力journalは、Rustの保存コンテナ内に保持する。

Worker世代が変わった後の古いcallbackはRust側で無視する。Controllerは公開フレームの階層変更を記録し、次の実入力境界で `RG_KEY_SAVE` を送り自動保存する。初期フレームと復元再生中の階層変更は保存を発生させない。設定からトップへ戻る場合も同じ保存経路を使い、IndexedDB transactionの完了後にWorkerと入力キューを終了する。失敗・入力取消時はゲーム画面に残る。文字編集中は草稿をCへ送って保存し、Enterで確定しない。キュー送信に失敗した場合は編集状態を失わない。

死亡・得点・勝利の終了表示、または正常な冒険終了で保存を削除する。ロードは再生後の最初の実入力待ちに到達した時点で成功とし、その保存を一度だけ削除する。失敗した復元では保存を消さない。削除時は候補と採用済みbytes・保存有無を先に破棄し、古いread/writeのcallbackを失効させる。ブラウザー層はread/write/deleteを発行順に直列実行し、古い書込みが削除後に復活したり、新しい自動保存が先行する削除で消えたりしないようにする。削除後は次の階層移動かトップへの復帰で新しい保存を作る。

## checkpointと入力再生

Cは外側command境界の状態を保存する。Rustはそのcheckpointと、以後Cが実際に消費した変換済みbyte/キーをjournalに記録する。表示だけの選択・スクロール・再描画・保存要求はC入力履歴へ混ぜない。

復元は新instanceでcheckpointを読み、journalを同じC経路へ再生して入力待ちを再構築する。Cスタック自体や生ポインターを保存しない。加速の行動間、アイテム・方向・文字・一覧の途中待ちもこの方法で再現する。保存済みキーを物理入力として再変換しない。

| 保存する持続状態 | 理由・担当 |
|---|---|
| `countch / direction / newcount` | 数値反復・Ctrl方向反復を次commandへ引き継ぐ。`command.c` のget/set |
| target-runのactive | 専用走行境界を通常走行と区別し、checkpoint復元後に同じ待ちを再構築する。経路・目的地は保存しない |
| `last_delt` | 再実行が直前方向を使う。`misc.c` のget/set。混乱前の記録順も維持する |
| statusの幅と値キャッシュ | raw画面の更新順とページ送りに影響する。`io.c` のstatus get/set |
| `line_cnt / newpage / maxlen` | 一覧の境界と窓幅。`things.c` のmenu get/set。外側境界ではline_cnt=0を検証する |
| `msgbuf / newpos`、`huh / prbuf / mpos` | 英語メッセージの蓄積・再表示・Moreによるlookに必要 |
| `oldpos / oldrp`、探索記憶、daemon/fuse | 復元後のlamp消去、可視画面、効果・周期を継続する |
| 各生成・追跡処理の作業用static | 使用前に再初期化されるものは保存しない。途中処理はjournalで再実行する |
| serializerのerror flags | 保存状態に含めず、各save/import開始時にresetする |

名称の静的登録、翻訳断片キュー、一覧の `lastfmt / lastarg` の生ポインターは保存しない。UTF-8編集中のC bufferはjournalで再構築する。MASTER専用数値編集やOSのhome・shell・score lockはWeb構成の保存対象外。

mazeのused/nexits、通路生成のisconn/ingraph、外見割当のused/metusedは各生成・初期化の冒頭でresetする。追跡・移動・投射の作業座標や表示文字bufferは使用前に構築する。正常mapに有効exitがないなど、以前の作業staticへ依存し得る不正fixtureを通常互換の根拠にしない。

WS_MISSILEのstatic boltは呼出しで必要属性を設定する。cur_weaponがない経路で残るo_launchは、通常weapon whichが非負の条件では有効launcherにならない。不正なwhichを追加してこの前提を破らない。復元後のplayitはoldpos/oldrpの初期値再代入を避け、保存済みのlamp消去状態を使う。

## C保存コンテナ

`logic/save_adapter.c` が `rg_core_save_bytes / rg_core_load_bytes / rg_core_save_free` を実装する。整数はlittle endian、上限4 MiB。旧端末版のFILE/XOR保存形式とは別で、未対応版を拒否する。

| byte offset | 内容 |
|---|---|
| 0 | `RG4SAVE\0`、8 bytes |
| 8 / 12 / 16 / 20 | container版1 / logic schema 2 / knowledge schema 1 / runtime schema 1、各u32 |
| 24 / 28 / 32 | logic / knowledge / runtimeのbyte長、各u32 |
| 36 / 40 | 完了turn数 / IEEE CRC32、各u32 |
| 44 | logic、knowledge、runtimeの順のpayload |

CRCは0〜39 byteと全payloadを対象とする破損検出で、認証ではない。各長さの和は入力長と一致させ、headerとruntimeのturnも照合する。

logicにはroomsとpassagesの参照空間、13種類のdaemon/fuse callback、monster/object/gold/hero参照、seed・dnum・max_hit等を保存する。knowledgeは `RGKN` 版1、24×80のglyph/standoutとcursor・属性、3,856 bytes。runtimeは `RGRT` と版・core word数・message byte数の16 byte headerに、18 u32のcore状態とmessage状態を続ける。末尾wordはtarget-runのactiveで、旧17 wordも受け付けてactiveを0として復元する。message状態は版1・newpos・143 byteのmsgbuf、計151 bytes。

読み込みは版・CRC・長さ・参照・範囲・終端・callback・割り当て上限を検証する。logic decoderはglobalを退避し、新規割り当てを追跡する。失敗時は元状態へ戻して新規割り当てを解放し、成功時だけ旧graphを解放する。分割したアイテムのlabel共有が残る旧graphは文字列addressを重複排除して一度だけ解放する。

GOLDのcount=0、食料や杖のwield、方向指定の絶対target、壁移動失敗後のnh、gone roomの負extent、passages[12]のゼロ初期値は原作で到達可能な状態として扱う。roomsとpassagesを同じ制約で検証しない。

## Rust保存envelope

`rogue-platform::Envelope` はformat・版・ABI・原作source hash・seed・名前・checkpoint_hex・inputs・input_index・checksumを持つ。JSON全体は16 MiB、checkpointは4 MiB、journalは65,536入力まで。現在の出力は版3で、版2と共通のpresentationは512 KiBまでに制限し、`lines / input / history / last_message` の構造も検証する。

`browser-display/src/save_loading.rs` は同じ `Envelope::parse` でファイル・IndexedDBの保存をゲーム開始前に検証する。拡張子だけでは受け付けず、形式・版・ABI・source・構造・上限・checksumを検査する。無効なファイルと選択取消では現在のセッションを終了せず、保存済みbytesも差し替えない。ファイルのbytesは検証成功の命令後にだけ復元元へ移す。ゲーム内のcheckpoint復元でも失敗した場合はトップへ戻してエラーを表示し、再開・新規開始を可能にする。

保存APIの保留状態は `browser-display/src/save_operations.rs` が所有し、要求ID・Worker世代・操作種別の一致で応答を受理する。Rustのブラウザー層は要求ごとの候補bytesを保持し、read/import/write callback内で復元元を差し替えない。Controllerの `save-accept` で採用し、`save-discard` で破棄する。新規開始とトップ復帰では保留要求を退役させ、遅延・重複応答が次のセッションの保存元を変更しないようにする。保存書込みはIndexedDB transaction完了後の受理で採用する。トップの「前回の続き」はIndexedDBの保存有無、書出しは受理済みbytesの有無を使い、ファイルimportだけで保存枠が存在すると扱わない。

画像の準備状態も応答件数ではなく、`tiles` と `pixels` の各セットの成功状態から決める。同じセットの重複応答は準備完了を早めず、成功・失敗の応答とも対象セットを渡す。

版3はUTF-8 byte・意味ID付きpresentationに加え、専用のtarget-run開始・継続・停止値をjournalへ保存する。開始値は通常command、継続・停止はrun-boundaryで再生し、文脈不一致を拒否する。旧版1のASCII入力履歴と旧版2のUTF-8 byte・意味ID付きpresentationも読み込めるが、両旧版へ専用run入力を混ぜることは許可しない。旧版1はルール状態を復元できるが、当時の意味付き履歴がないため過去メッセージの日本語を完全には復元できない。checksumは破損検出であり署名ではない。表示モード・倍率・アニメーション・テーマ・利き手は別のlocalStorage設定で、ゲーム保存へ含めない。持ち物一覧の閲覧状態は前述の冒険・保存slot単位のUI情報として別保存し、Cの保存bytesへ含めない。

## 本番・ビルド・検証の分離

`start.ps1` は作品内の開発用 [tools/server.mjs](../tools/server.mjs) へ配信対象を渡す。共有入力に必要なCOOP/COEPヘッダーとWasmのContent-Typeは本番の静的配信側でも設定する。同じ配信元の既存サーバーは再利用し、別プロセスの終了や自動ポート変更は行わない。originが変わるとIndexedDB保存枠も変わるためである。

通常Wasmに `RG_TEST_FIXTURES` や `RG_TEST_HOOKS`、Rustの `test-hooks / browser-test` を含めない。試験用buildには `game` 以外の出力名を要求する。ブラウザーの観測・操作exportは `browser-test` featureの専用 `browser-test.js / browser-test.wasm` に限定する。テストアダプターは検証側でbindingを置き換えて注入し、本番JSから読み込まない。

通常ビルドは自分の専用コンパイラー領域だけを終了時に閉じる。他の中断した実行の回収は検証ツール・明示的な開発操作に限定する。配布に必要な `game.wasm / browser-ui.js / browser-ui.wasm / build-manifest.json` は保持する。ビルド・検証の実行方法は [README](../README.md) と [tests/README](../tests/README.md) に置く。
