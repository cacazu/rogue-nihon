# Space 待ちの調査（2026-10-08）

対象は Rogue ブラウザー版の製品 C/Rust/Wasm。全 C ソースの `readchar`、`getch`、`getchar`、`fgets`、`wgetnstr`、`wait_for` と `show_win` の呼び出し・入力比較を照合した。Space の文字定数・32・0x20 の比較も検索し、地形の空白判定を入力待ちと区別した。

Space を受け取る待ちの実装は、製品の C では6か所の `rg_wait_for(' ', ...)` 呼び出しと、`io.c` の2か所の直接ループ。以下が全ての利用場面で、ボタンは Rust が意味に応じて作る。

| 利用場面 | C の経路・条件 | ウインドウの操作 |
| --- | --- | --- |
| 所持品 `i`、品物選択中の `*`、発見一覧 `D` の最終ページ | `inventory` / `discovered` → `add_line`。重ねる表示では専用ウインドウ分岐、画面を切り替える表示では一覧ウインドウ分岐。 | **閉じる**。Space・Enter・Esc、またはボタン。品物選択の中から開いた場合は元の選択へ戻る。 |
| 長い一覧の途中 | `add_line` の `line_cnt >= LINES - 1` かつ残りの行がある場合。発見一覧は複数ページになり得る。 | **次のページ**。Space・Enter、またはボタン。最終ページは閉じる。C はこの待ちで一覧取消を受け付けないため、従来の Rust の Esc 対応も次のページとして処理する。 |
| 所持品を「1行ずつ表示」に設定したとき | `inventory` が `msg_esc = TRUE` にして `add_line` → `msg` → `endmsg`。前の品物が表示されていると次の品物の前で待つ。 | **次の品物**、**閉じる**。Enter は Space に変換して送り、Esc と閉じるボタンは元の C の取消へ渡す。最後の品物を出した後は一覧が終了する。発見一覧の1行ずつ表示は `msg_esc` を立てず、通常ログとして進む。 |
| 全操作ヘルプ `?` → `*` | `command.c help`。単一コマンドの説明はこの待ちに入らない。 | **閉じる**。Space・Enter・Esc、またはボタン。ヘルプ内のスクロールは入力待ちではない。 |
| ゲーム内設定 `o` の編集終了後 | `options.c option`。Esc で編集を終えた後、または全項目を編集した後。 | **閉じる**。Space・Enter・Esc、またはボタン。編集中の Enter は値を保持して次の項目へ進む操作。 |
| 魔法探知の薬 | `potions.c` の `P_TFIND` → `show_win`。階の品物または敵の持ち物から魔法の品物を実際に検出した場合。対象がない場合は通常メッセージだけ。 | 検出マップの **閉じる**。Space・Enter・Esc、またはボタン。 |
| 食料探知の巻物 | `scrolls.c` の `S_FDET` → `show_win`。床に食料がある場合。対象がない場合は通常メッセージだけ。 | 検出マップの **閉じる**。Space・Enter・Esc、またはボタン。 |
| 勝利の祝福から戦利品の精算へ | `rip.c total_winner`。 | **結果を見る**。Space・Enter、またはボタン。C が品物の価値を計算した後の Enter 待ちは **スコアを見る**。 |
| 旧来の通常メッセージの `--More--` | `io.c rg_wait_message_ack`。Rust のメッセージページング方針が legacy の場合だけ。 | **次のメッセージ**。通常ブラウザーは `log` 方針なのでこの待ちは発生しない。旧セーブ復元時は記録済みの入力区間を再生し、その後のライブ入力はログ表示になる。 |

空の所持品一覧と、通常表示で品物が1つだけの一覧はメッセージとして直ちに戻り、Space 待ちはない。所持品の最大容量は23枠なので、通常の全所持品は長い発見一覧のようには増えない。品物選択の `*` は、飲む `q`、読む `r`、食べる `e`、構える `w`、着る `W`、指輪をはめる `P`、置く `d`、名前を付ける `c`、投げる `t`、杖を使う `z`、識別効果中の品物選択が同じ `inventory` の経路を使用する。投げる・杖は方向指定の後に品物を選ぶ。

死亡画面と終了・精算画面には Enter の確認待ちがある。Space 専用の待ちではなく、「スコアを見る」「終了する」のボタンを用意した。移動・戦闘・効果の通常メッセージはログに入り、Space を挟まなくてもゲームのコマンドが完了する。

## 製品ビルドに含まれない待ち

- `wizard.c show_map` の開発用全体マップは `MASTER` 条件内で、`show_win` の Space 待ちを使用する。
- `things.c new_thing` の不正な品物種類を生成した際の `wait_for(' ')` も `MASTER` 条件内。
- 開発用の床の全品物一覧・品物仕様一覧は上記の共通 `add_line` を使用する。コマンドの呼び出し元は `MASTER` 条件内。
- 製品の `build.ps1` は `ROGUE_LAYERED` を指定し、`MASTER` を指定しない。端末版のシェル復帰は Enter 待ちで、ブラウザー版ではシェルを起動しない。

## 検証

`node tests/browser-smoke/space-waits.mjs` で実 Playwright/Brave、Worker、SAB、Rust、C 本体を操作する。14ケースの結果と現行ソース・Wasm の SHA-256 は [evidence.json](../tests/browser-smoke/output/space-waits/evidence.json) に保存する。

通常一覧・ヘルプ・設定・3種類の一覧表示は製品 Wasm で確認。長い発見一覧、薬・巻物の検出、勝利、空・1品物の所持品、制御した戦闘は `tests/game-fixtures.c` の再現状態を実 C の API で作り、同じ C 本体と Rust を動かす。JavaScript で画面やゲーム状態を捏造した確認ではない。テスト用の状態作成コードは製品 Wasm にリンクしない。legacy の通常メッセージ待ちはテスト用 Worker で方針を切り替えて確認し、製品 Worker の `log` 方針は維持する。

所持品の閉じる操作で C のターン・食料・乱数を含む観測値が変わらないこと、Space を入力せずボタンだけで各待ちを抜けること、検出中も既知の背景マップを保持することを検査する。PC・スマホ、保存・復元、選択・方向・文字入力の関連確認は `game-windows.mjs`、画面配置は `layout.mjs` に記録する。
