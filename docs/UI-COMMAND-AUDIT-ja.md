# 状態に応じた操作の表示とコマンド確認

2026-10-08。通常マップに無関係な操作を常設せず、現在の入力待ちと公開済みの情報から必要な操作を選ぶ。

## 表示条件

| 場面 | 表示する操作 |
| --- | --- |
| 通常のスマホマップ | 8方向の移動、中央の待機、持ち物、操作一覧。続ける・キャンセルは表示しない。 |
| 階段に乗っている通常マップ | 上記に「階段を下りる」を追加。階段から離れる・下の階へ移ると非表示。Cが表示した足元を使用する。 |
| 投げる方向を選択中 | オレンジ色の8方向とキャンセル。待機、持ち物、操作一覧、階段、続けるは表示しない。 |
| 品物・方向・文字・確認の入力待ち | 入力に対応するゲームウインドウの候補、確定、取消など。マップの操作ボタンは表示しない。 |
| 一覧・検出マップ | 最終ページは閉じる、途中は次のページ。通常マップの続けるボタンで代用しない。 |
| 詳細表示 | 戻る。元のアイテム操作へ戻り、さらに持ち物へ戻れる。 |
| 結果・スコア | 現在の段階に応じた結果を見る・スコアを見る・終了する、トップ画面に戻る。通常マップの操作は表示しない。 |
| ブラウザー設定 | 保存が存在するときにダウンロード、画像表示のときに拡大率。文字表示には拡大率の操作を出さない。 |

アイテム操作は種類と装備状態から飲む・読む・食べる・構える・着る・脱ぐ・指輪をはめる／外す・杖を使うを選ぶ。別の鎧を着ている間は「着る」を出さない。種類別の候補選択でも、装備済みの武器／指輪、装備枠が埋まっている鎧／指輪、鑑定済みで名付けできない薬・巻物・指輪・杖を除く。武器と鎧の個別の名付けは維持する。

判定に用いるのは、Cがすでに公開した品物記述の種類、装備状態、鑑定済みかどうかと、表示済みの足元。階段・扉・見えている罠の上では、配置できない「落とす」を出さない。隠れた呪い、補正、未鑑定の効果、未表示の世界情報は参照しない。呪いによる失敗、足元が不明な場合の配置の失敗などは元のCの判定を通す。キーボードで直接入力した元のコマンドの判定も保持する。

## 処理の構成

Rust/Bevyが `ui.map_controls` とウインドウの選択肢を作る。Canvasはこの一覧を描画し、ボタンのキーをRust入力へ送る。Cからの `item_action` は、今どの用途で品物を選んでいるかを示す表示用のタグで、文字列やログには表示しない。候補の絞り込みはRust側で行い、Cの入力待ち、ルール、乱数、ターン、保存形式は変更しない。

## 確認するコマンドと後続処理

`tests/browser-smoke/inventory-actions.mjs` は原作 `logic/extern.c` のヘルプからコマンド集合を取り出し、全63コマンドとの一致を検査する。2つの修飾キー説明行はコマンドではないため、Shift/Ctrlと8方向の計16通りを別途操作する。各コマンドは方向・品物・文字などの入力を終え、通常のコマンド待ちへ戻ったことを検査する。

| 対象 | 最後まで行う操作 |
| --- | --- |
| 移動、走行、通路を追う移動、数字による反復、繰り返し | 実際のC移動を完了。投げた後の繰り返し、取消後の移動も確認。 |
| 投げる、杖、連続攻撃、拾わずに移動、罠の確認 | 方向の選択・取消、必要なら品物の選択、その後の効果・戦闘が完了するまで確認。 |
| 飲む、読む、食べる、構える、着る、脱ぐ、指輪をはめる／外す、落とす | 対象選択と実行。左右の指輪、装備後のメニュー更新、呪われた装備の失敗、配置失敗後の通常操作も確認。 |
| 名付け | 実際の文字欄に入力して確定。未確定の取消で名前が変わらないことも確認。 |
| 持ち物、1品物の確認、詳細 | 一覧から品物と操作を選択。詳細から操作へ戻り、一覧へ戻り、閉じるまで確認。 |
| 識別の巻物 | 巻物を読むだけで終えず、二段目の対象選択と識別まで確認。 |
| 魔法・食料の検出 | 品物選択、検出マップの表示、閉じる、ターン更新まで確認。 |
| 発見一覧 | 4分類とすべて表示、全ページの送り、最終ページを閉じるまで確認。 |
| ヘルプ、記号の説明 | 一覧、スクロール、閉じる、個別コマンド／記号の入力と説明まで確認。 |
| ゲーム内設定 | 6個の真偽値、戻る、値の保持、3種類の一覧形式、名前・果物・ファイル名の編集、終了後の閉じるまで確認。 |
| 探索、待機、拾う、階段、装備表示、状態、再表示、直前メッセージ、バージョン | 実行後の結果と通常操作への復帰を確認。階段ボタンは乗る・離れる・降りる場面をタッチ操作。 |
| 保存・シェルの元コマンド | ブラウザーでの案内を確認。保存本体は設定から実行し、ダウンロード、トップへ戻る、ロード後の通常操作まで確認。 |
| 終了、死亡、勝利 | 終了確認の両選択肢、精算・スコアの各入力待ち、トップへの復帰まで確認。 |

`context-controls.mjs` は各入力の前後で、現在の状況に対応しないボタンがないことも検査する。`throw-direction.mjs` は8方向、修飾キー、取消、数値反復、保存復元を確認する。旧ビルドへ同じCキー列を渡し、全20状態word・入力位置・全トレースを比較する。

実ブラウザーのPlaywright検証は隔離したプロファイルとテスト用originを使う。通常版、再現状態を作るfixture版、変更前の独立したWasmを使い分ける。fixtureは製品にリンクせず、JavaScriptでゲームの結果を捏造しない。スマホ表示はChrome／Braveのタッチ・画面サイズのエミュレーションである。

実行結果とスクリーンショットは `tests/browser-smoke/output/context-controls/`、`output/inventory-actions/`、`output/throw-direction/` に保存する。

```powershell
.\build.ps1
.\build.ps1 -SkipRust -SkipCatalogGeneration -TestFixtures -OutputName game-fixtures -KeepArtifacts
node tests/browser-smoke/context-controls.mjs
node tests/browser-smoke/inventory-actions.mjs
$env:ROGUE_INVENTORY_MOBILE='1'
node tests/browser-smoke/inventory-actions.mjs
Remove-Item Env:ROGUE_INVENTORY_MOBILE
node tests/browser-smoke/throw-direction.mjs
```

比較用の変更前Wasmは `output/context-controls/before/build/` に保存した。別環境で再実行するときは同じC fixtureを含む独立した変更前ビルドが必要。

## 実測結果

全て成功。最終ビルドでは、ChromeのPC表示とBraveのスマホ表示のそれぞれで、全63コマンド・16修飾キー入力・数字による反復・終了確認後の処理の81項目を再実行した。コマンドの後続入力を終えて通常操作へ戻ること、終了時は結果・スコア処理を終えることを確認した。

Braveの状態別検証は63項目、変更前との比較は62入力列・527チェックポイント。Chromeでも状態別61項目の全体確認に加え、最終の階段・配置・全画面取消を3項目で再確認した。各比較では全20状態word・入力位置・全トレースが一致した。

アイテム操作の全体確認158項目ずつ、投げる方向65項目、Canvas全体31項目も成功した。これらの一式確認後に追加した足元による「落とす」の表示条件は、最終ビルドの状態別検証と全コマンド再確認で検証した。一式確認の結果は `output/inventory-actions/{chrome,brave-mobile}/full-evidence.json` に保持し、最終の全コマンド確認は同じ場所の `evidence.json` に保存した。

最終ビルドのLAN HTTPS検証8項目、タッチ入力Chrome／Brave各13項目、Node回帰34項目、Bevyエンジン46項目も成功。比較・操作中のブラウザー例外、翻訳fallback、未登録UI IDは0だった。通常マップ、方向選択、階段、装備、名付け候補、文字表示の設定、全画面、保存復元のスクリーンショットを目視確認した。

実行結果の一覧、各検証が使った版、最終ビルドのSHA-256は [verification.json](../tests/browser-smoke/output/context-controls/verification.json) に保存した。最新ビルドで再実行した検証は `latest_build: true` として区別している。
