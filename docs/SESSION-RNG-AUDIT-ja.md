## 幻覚状態で乱数が進んだ理由

元の C では `endmsg` が前のメッセージを表示している場合に `look(FALSE)` を呼ぶ。またコマンドを取り消して次の入力へ戻ると、通常のコマンド処理が `look` を呼ぶ。幻覚状態で周囲に敵などが見えていると、この描画が `rnd` を呼ぶ。ターン数が増えなくても乱数が進み得る。

Playwright の既存 C 再現状態 `hallucination`、シード17では、`q` の選択を開いた時点の乱数状態 `2715873405` が、空の薬一覧を `*` で要求してコマンド待ちへ戻ると `2617301995` になった。ターン数は0のまま。この進み方は元の C と現行 C/Rust の同じ入力による比較でも一致し、今回追加した候補表示のせいで増えた乱数消費ではなかった。

## 入力変更の具体例と限界

変更前の `i → Enter → .` は、Enter と `.` が Space 待ち中に無視され、ターン0で止まる。現行版では Enter がウインドウを閉じ、`.` が休憩として実行され、ターン1になる。Esc も同様。これは意図した入力機能の変更である。現行版の `i → Enter/Esc → .` と、変更前の `i → Space → .` は状態と入力位置が一致した。

この調査は上記の実行条件とソース差分を根拠とする。あらゆるシード・状態・入力列の網羅証明ではない。特に「画面操作なら必ず乱数が進まない」という一般化はしない。幻覚時など、元の C 自身が描画で乱数を使う仕様は残っている。
