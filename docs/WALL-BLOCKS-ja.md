# 縦横共通の石壁ブロック

2026-10-11。横壁 `-` と縦壁 `|` を、同じ正方形の石のブロックへ統一した。各マスを全面不透明のブロックで埋め、壁の角も同じ幅でつながる。回転・方向別の画像選択は行わない。

表示済みの意味IDは従来どおり49種。縦壁・横壁のIDと説明は維持し、両方のmanifestの `image` を `terrain.wall.png`、`rotation` を0にした。共通化により読み込むPNGは各セット45枚になった。Rustの読み込み検査はmanifestの重複を除いたファイル数を使う。

- ドット絵: `web/assets/pixels-v2/terrain.wall.png`（32×32 RGBA、8色以下、全面不透明）
- イラスト: `web/assets/tiles/terrain.wall.png`（96×96、同じ石ブロックを最近傍で拡大）
- 生成元: `web/assets/walls/source.png`
- 生成プロンプト・梱包内容・SHA-256: `web/assets/walls/generation.json`

組み込みImageGenで新規生成し、中央の穴を埋める修正を行った。生成指示は、縦横共通・回転なし・正方形の灰色の石・暗い輪郭・明るい縁・不透明な中央・32×32の論理画素・少ない色数。`node tools/pack-walls.mjs` で原画像から両サイズを再梱包できる。アトラス／ドット絵の再梱包処理もこの共通壁を維持する。

壁と弾道の意味IDの区別は変更しない。Cの移動・衝突・扉・探索・乱数・セーブ形式も変更しない。画像の選択と検査はRust、JavaScriptは既存の画像読み込みとCanvas描画を使う。

検証は `tests/pixels.test.mjs`、`tests/tiles.test.mjs`、Rustの読み込み検査、Playwrightの `tests/browser-smoke/wall-blocks.mjs` と `canvas.mjs` で行う。各表示モード・倍率・PC・スマホ幅の実ゲーム、壁への移動・扉への移動、表示操作でゲーム状態が変わらないこと、スクリーンショットを確認する。

今回の結果はPlaywright 48項目成功（壁16、主要操作32）、Rust 23項目成功、Node 25項目成功。ドット絵32／64／96／128px、イラスト16／24／32／48／64px、PCとスマホ幅390px・DPR 2で確認した。画面の壁画素を共通PNGの拡大結果と比較し、縦壁・横壁とも一致した。壁との衝突、扉への移動、既存の持ち物・保存・復元・全画面なども成功し、ブラウザー例外は0。実機スマートフォンでの手動操作は含まない。
